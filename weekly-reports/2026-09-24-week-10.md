The supervisor asked the team to study and implement the Graph Burning problem
on the existing Giraph setup. The related diffusion models discussed were

## Error and fix

The first run passed `3,8,6` through Giraph's `-ca` argument. Giraph treated
commas as separators between configuration settings, set the sequence to `3`,
and rejected `8`. That run failed before YARN job submission. We changed the
configuration value and Java parser to use `3:8:6`, copied both corrected
files to the server, rebuilt, and reran successfully.

After the successful run, `ps` showed no NodeManager process. Starting it again
registered a new node, while ResourceManager temporarily still displayed the
old registration with three containers. We checked that only one NodeManager
process existed and that no application was `ACCEPTED` or `RUNNING`, then
stopped YARN for a clean restart. This is an environment recovery step, not a
required part of the Graph Burning algorithm. The repeatable checks are in
the [daily lab startup guide](../docs/DAILY-LAB-STARTUP.md).
