# Week 10 Report — 18–24 September 2026

**Project:** Distributed graph algorithms for social network problems using Apache Giraph  
**Status as of 23 September:** Graph Burning simulator working on a verified small graph

## Faculty direction

The supervisor asked the team to study and implement the Graph Burning problem
on the existing Giraph setup. The related diffusion models discussed were
Independent Cascade (ICM), Linear Threshold (LTM), and Susceptible–Infected–
Recovered (SIR). We have documented the confirmed model names and their
different spreading rules in the [study note](../study-material/graph-burning-and-diffusion-models.md).

## Work completed

- Started HDFS and YARN as `hduser` after the lab machine was restarted.
- Verified NameNode, DataNode, SecondaryNameNode, ResourceManager and
  NodeManager with `jps` and one `RUNNING` YARN node.
- Studied Graph Burning as a process with one newly selected source each
  round and fire propagating one edge per round.
- Created a nine-vertex undirected path divided into three input files.
- Calculated the expected burn rounds manually for sources `3:8:6`.
- Added `LearningGraphBurningComputation.java`, a Giraph simulator that stores
  the first burn round at every vertex.
- Added a runner script and a Hinglish code explanation.
- Uploaded the three files into one HDFS input directory.
- Built the Giraph modules and confirmed the new `.class` exists inside the
  shaded examples JAR.
- Ran the simulator successfully and checked all nine output values against
  the manual table. The graph was fully burned by round 3.
- Added a separate [Maven build explanation](../study-material/maven-build-workflow.md)
  so the team can decide independently when to rebuild.

## Error and fix

The first run passed `3,8,6` through Giraph's `-ca` argument. Giraph treated
commas as separators between configuration settings, set the sequence to `3`,
and rejected `8`. That run failed before YARN job submission. We changed the
configuration value and Java parser to use `3:8:6`, copied both corrected
files to the server, rebuilt, and reran successfully.
