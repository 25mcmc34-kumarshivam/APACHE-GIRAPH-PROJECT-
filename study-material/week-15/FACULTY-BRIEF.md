# Week 15 — concise faculty explanation

Our project studies distributed graph algorithms with Apache Giraph on a single-node Hadoop/YARN lab setup. This week's main experiment was **standard Graph Burning with an input-specified ignition schedule**. It is separate from the earlier limited-neighbour Python exercise.

We represented a synthetic 10×12 undirected grid as 120 vertex records and 218 edges, split across four text files. Each record contains the vertex ID, its chosen source round (zero if not chosen), and adjacency entries. The four files form **one graph**; Giraph reads their common HDFS directory. We selected eight **seeded random eligible** ignition vertices, `15:104:35:101:41:111:83:86`. This is deliberately **not** an optimization or minimum-burning-number claim.

In round 1 only source 15 ignites. In each later round, vertices first burned in the preceding round spread fire across one edge, while that round's new source ignites. Python validates the input, simulates each round, writes the expected final output and exports PNG/GraphML snapshots. Giraph independently processes the same four input files and writes its actual result. We compared all 120 final rows with `diff -u`: **exit code 0**. After eight rounds, **119 vertices are `B` and vertex 85 is `NB -1`**. The third output column is the *first* round in which each vertex burned.

The Python round pictures show which vertices had burned after each round. They are visualization aids, not output produced by Giraph. The match on this example supports correctness for this selected schedule; it is **not a proof** for all graphs or that eight rounds/sources are optimal. A later task is to compare selection methods, including an explicit optimization baseline, on datasets beyond this synthetic grid.
